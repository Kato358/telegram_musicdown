# v0.1.5 长期运行的 RSS 不再只增不减；日志只留最近 500 行

现场是：容器刚起来约 100MB，闲置（自己都不用）长时间运行后涨到 550MB，重启又回到 100MB。上一版的 `MALLOC_ARENA_MAX=2` 与周期 `gc`/`malloc_trim` 处理的是「大块临时分配还给了 glibc 但没还给内核」，这次查出来的是**真的在攒 Python 对象**。

根因在 Telegram 客户端这一侧：登录账号的客户端只调 `client.connect()`（向导要自己控验证码与两步密码，走不了 `start()` 的交互式授权），而 Kurigram 里**唯一消费 `dispatcher.updates_queue` 的地方**是 `Dispatcher.handler_worker`，它只在 `Client.start()` → `initialize()` 里被创建。于是 Telegram 推给这个会话的每一条 update（新消息、编辑、已读、在线状态……）都被塞进那个**无界** `asyncio.Queue`，永远没人取——进程不重启就按时间线性涨。实测约 **1.3KB/条**，闲置在线的账号几天就能堆出几百 MB。这不是本项目的用法错误：上游 [kurigram#467](https://github.com/kurigram-org/kurigram/issues/467) 记的就是这件事，至今 Open。

- **连接后排空并丢弃 update 队列**：本客户端不注册任何 handler，update 对业务没有任何用处，取走丢掉即可——队列随取随空，占用回到常数级；`disconnect()` 时把排空协程停掉。若将来真有人启动了 Dispatcher（`handler_worker_tasks` 非空），排空自动让位，不去抢它的 update
- **顺手补掉两处只写不删的负缓存**：歌词失败负缓存与封面失败负缓存（TTL 600s）早先只增不减，「查得越多涨得越多」；现在过期即删、并按条数封顶 512（与命中缓存同口径）
- **日志改成只保留最近 500 行**：不再按 `10MB × 5` 轮转（长期运行的容器会攒下最多 50MB 磁盘，以及五个再也不会更新的 `app.log.N`）。现在是追加写 + 超过 500 行即裁到 400 行——裁到 400 而不是刚好 500，是为了把「写满一条就重写一次全文件」摊成每 100 行一次；`app.log` 行数因此**恒不超过 500**。旧版旋转备份 `app.log.1…N` 在启动时清掉（只认这个命名），日志页的中英文案同步改写
- **要留证请先在日志页下载**：按行封顶的唯一代价是**没有历史**，`app.log` 里只有最近 500 行
- **测试**：`tests/unit/test_user_client.py` 新增「连上后 update 随取随空」「断连后停下」「Dispatcher 真在跑时让位」；`tests/unit/test_logfile.py` 新增「文件行数不超上限且留的是连续的一段尾巴」「已有旧文件也计入行数」「traceback 按行计入」「旧旋转备份被清掉、当前文件不动」

## 验证与已知残留

用真实 Kurigram 库做冒烟：同一批 200 个 `Updates` 容器（4000 条音频 update）喂给未启动 Dispatcher 的客户端 → 队列积压 4000 条、traced 增长 5.08MB（1271 B/条）；换成带排空的 `UserClient` → 结束队列为 0，瞬时上限就是一批。业务代码的 `ruff` / `mypy` / `pytest`（417 例）全过。

**上游残留（本仓库不修，只记录）**：`TCP.close()` 不 `shutdown()` 它那个 `CryptoWorker` 线程池、`Client.terminate()` 不关 `Client.executor`——每次会话重连（网络抖动、服务端 null packet）与每次重建 Client 各漏掉若干线程。判断方法：`docker exec musicdown sh -c 'grep Threads /proc/1/status'`，若 Threads 到几百上千就是它（重启容器即清零）。

## 镜像

**仓库改名后镜像包名跟着变了**：`ghcr.io/kato358/telgram_musicdown` → `ghcr.io/kato358/telegram_musicdown`。旧包停在 0.1.4、不会再有新版本，老部署把 compose 里的 `image:` 改一行就能跟上（容器名、卷、环境变量都不用动）：

```bash
docker pull ghcr.io/kato358/telegram_musicdown:0.1.5
docker pull ghcr.io/kato358/telegram_musicdown:0.1
```

`:latest` 仍跟着 `main`；`:0.1` 随本条移动到 0.1.5。要锁版本就把 compose 里的 `image:` 钉到 `:0.1.5`。升级后第一次启动会清掉 `data/logs/` 下旧的 `app.log.1…5`，日志里有一条 INFO 说明。
