## 1. 引言

### 1.1 目的

本文档定义一款面向个人使用的 Telegram 音乐资源下载与管理工具的功能、约束与验收标准。读者为产品决策者与后续实现人员。

### 1.2 问题陈述

Telegram 上大量音乐以频道/群组消息（`audio`、MIME 为 `audio/*` 的 `document`）形式发布。现有通用媒体下载器（如参考项目）能批量拉媒体、用 Bot 下发链接、自定义路径前缀，但：

- 不以音乐检索为中心，缺少跨频道关键词搜索与结果预览。
- Web 端仅展示下载队列/已完成列表，频道与命名配置页处于未完成状态。
- 文件名只支持 `message_id` / `file_name` / `caption` 拼接，无法使用艺人、专辑、曲名、音质等音乐字段。
- 媒体类型过宽（照片、视频、动画等），与本产品目标不符。

本产品收敛为：**可自建频道源 → 搜索/浏览音乐 → 试听 → 下载 → 按模板落盘 → Web 管理标签与任务**。

### 1.3 产品愿景

本地常驻服务：用 Telegram 用户账号（User Client）读取已加入的频道/群组，用可选 Bot 接收链接下载指令；提供 Web 控制台管理频道、搜索、试听、标签、任务与命名规则。下载结果按用户模板写入本地音乐库。

### 1.4 范围

**范围内**

- 频道/群组作为音乐源的增删改、启用/停用。
- 在已配置源中按关键词、元数据、日期、时长、音质检索。
- 单条 / 批量 / 链接 / 转发消息下载。
- 自定义文件名与目录模板（默认 Navidrome/Jellyfin 友好的 Artist/Album/Track）。
- Web 查看任务、历史、失败重试；搜索与已下载试听；读取/编辑音频标签；响应式布局与暗色主题。
- 可选 Bot：向机器人发送 `t.me` 链接或转发音频后下载；下载完成可通知。

**范围外（本期不做）**

- 破解私密内容、绕过 Telegram 限制、未授权抓取未加入频道。
- 商业分发、公网多租户 SaaS。
- 视频、图片、`voice`、视频内音轨等非 `audio` / `audio/*` document 媒体（封面图仅作为音频附属元数据）。
- 在未添加为音乐源的对话中搜索。
- 云盘同步（rclone / 阿里云盘）——参考项目有，本期不纳入核心。
- 音乐版权授权、付费曲库对接。

### 1.5 术语

| 术语 | 定义 |
| --- | --- |
| User Client | 以用户账号登录的 Kurigram 客户端，可读取频道历史、执行对话内音频搜索。 |
| Bot | BotFather 签发的机器人，用于接收命令与链接。Bot **不能**直接读取任意频道历史，链接解析仍走 User Client。 |
| 音乐源（Source） | 用户添加的频道或群组，用 `chat_id` / `@username` / 邀请链接标识。 |
| 音频消息 | Telegram `Message.audio`，或 MIME 为 `audio/*` 的 `document`。 |
| 模板 | 含占位符的字符串，用于生成相对路径与文件名，例如 `{artist}/{album}/{track:02d} {title}`。 |
| 游标 | 某音乐源已扫描到的 `last_message_id`，用于增量同步。 |

### 1.6 合规声明

本工具仅供用户下载其有权获取的内容（例如自己上传、已获授权、或法律法规允许的个人备份）。使用者对频道内容的合法性自行负责。实现上不提供批量爬取公开全网音乐站、不绕过付费墙。

## 3. 用户与使用场景

### 3.1 角色

| 角色 | 说明 |
| --- | --- |
| 本地管理员 | 本机唯一用户。配置 API、登录 Telegram、管理频道与模板。 |
| Bot 授权用户 | `allowed_user_ids` 中的 Telegram 用户，可向 Bot 发链接。默认仅登录账号。 |

无多租户、无普通访客。Web 用本地密码保护即可。

### 3.2 核心场景
1. **首次启动**：Docker 部署后浏览器打开 Web，`/setup` 向导三步走完——① 密钥与代理（`api_id` / `api_hash` / 可选 `bot_token` / 可选代理）② 手机号验证码登录（生成 `sessions/` 会话文件）③ 选音乐源（可从账号对话中推荐或粘链接）。第 3 步可跳过：**放行判据是密钥 + 登录**，向导内随时能进控制台，源之后在「音乐源」页补。
2. **添加频道**：粘贴 `@channel`、`https://t.me/xxx` 或数字 id；系统解析标题、成员可见性、能否访问历史。
3. **搜索下载**：输入「周杰伦 晴天」，在已启用源中搜音频标题/表演者/文件名/caption，勾选结果批量下载。
4. **链接下载**：把 `https://t.me/c/123/456` 发给 Bot 或贴到 Web，解析后下载该条（若是相册/连续音频可展开）。
5. **整理曲库**：按 `{artist}/{album}/{title}` 落盘，写入 ID3，重复曲跳过。

> v0.10：原第 5 条「盯更」（源自动同步新消息）已取消——不做任何同步操作，入库只由上面第 3/4 条的手动动作触发。

## 4. 总体设计约束

### 4.1 运行形态

- 单机服务：一个后端进程 + 静态/内嵌 Web。
- 默认绑定 `127.0.0.1`，可改为 `0.0.0.0`（远程访问必须启用 Web 密码）。
- Linux + Docker 为主运行环境（Dockerfile + docker-compose.yml）；Windows 保留为开发环境（`python -m app`）。


### 4.2 技术选型（已锁定）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| Telegram | Kurigram User Client | 与参考项目一致；频道历史与对话内 `filter=Audio` 搜索走用户协议 |
| Bot | 同一进程内 Kurigram Bot Client | User 下载、Bot 收指令；链接解析仍走 User Client |
| 后端 | Python 3.11+ + FastAPI | 异步下载、SSE/WebSocket 推进度 |
| 前端 | Svelte 5 + TailwindCSS + shadcn-svelte（Vite 构建） | 参考项目 Layui 配置页未完成，不继承；Svelte 编译期产出小、无虚拟 DOM，长驻本地服务不需要重运行时；Tailwind 暗色一等公民；shadcn-svelte 提供可改写的可访问组件 |
| 音频标签 | mutagen | 写 ID3/Vorbis |

### 4.3 Telegram 平台硬约束（必须在 UI 中提示）

1. **搜索不是全网搜歌**。逐源模式（默认）只能搜：当前账号已加入、且已添加为音乐源的对话；全账号模式（`search_mode=global`）用服务端 `messages.searchGlobal` 搜**账号已加入的全部对话**（含未添加为源的频道），但仍搜不到账号没加入的对话。
2. **私有频道** 必须先用该账号加入，否则链接解析失败。
3. **Bot 无法代替 User Client 扫频道**。无 User 登录时，Bot 只能处理「用户转发到 Bot 的音频文件」本身。
4. 下载受 Telegram 速率与洪水限制；并发默认 3–5，可配，超限要排队与退避。
5. 大文件（>2GB 视账号类型）可能失败，需记录错误而非静默丢弃。

## 5. 功能需求

优先级：P0 首版必做；P1 首版强烈建议；P2 后续。

### 5.1 账号与会话

**FR-AUTH-01（P0）首次登录**

- 配置 `api_id`、`api_hash`（来自 https://my.telegram.org/apps）。
- **前置条件可见**：密钥未配置时不发送验证码，直接说明「先去第 1 步保存密钥」；手机号必须带国家码，格式不对在本地拦下并给示例。
- 支持手机号 + 验证码；若开启 2FA，在 Web 内输入云密码（界面按服务端返回展开密码框，不要求用户预先判断账号是否开了 2FA）。
- 手机号与验证码只走本机服务，不写日志（FR-OPS-03）。
- 已有有效会话时不再要求验证码，直接告知会话仍有效。
- **连不上 Telegram（代理不可达 / 网络不通）必须给出可操作原因**（含当前代理的协议与地址），不得只回「请求失败」或长时间无响应。
- Session 落在本地 `sessions/`，权限仅当前用户可读。
- 登录成功后展示账号显示名、用户名、是否为 Premium。

**FR-AUTH-02（P0）会话保活与失效**

- 启动时复用 session；失效则 Web 提示重新登录，不删除历史任务。
- 支持登出（删除 session，不删下载文件与数据库）：入口在设置页「Telegram 账号」的「退出登录」，删除 `sessions/` 下的 User 会话文件后才算退出（留着会话文件下次启动会判「已有有效会话」直接放行）；Bot 会话是独立身份，token 未换就保留。退出登录**只退 Telegram 账号，不退 Web 控制台**（不动会话 cookie）——退出后放行判据不满足，前端闸门把人送回向导第 2 步重新登录。

**FR-AUTH-03（P0）代理**

- 支持 SOCKS5 / HTTP 代理（host、port、可选用户名密码）。
- User Client 与 Bot 共用同一代理配置。
- 代理在初始化向导与设置页都可保存；**未连接的客户端保存后立即用新配置**，已有已连接客户端时明确提示「重启服务后按新配置重连」。
- 代理的用户名/密码不回显到 Web（NFR-02）；用户只在表单里改地址/端口时，**不得静默丢弃**已有凭据。

**FR-AUTH-04（P1）Bot Token**

- 可选。未配置时 Web 链接下载仍可用。
- `allowed_user_ids` 默认 `me`；非法用户消息忽略。
- 配置了 token 时，登录成功后一并启动 Bot；**Bot 起不来不阻断登录与 Web 功能**，原因记日志。
- token 可在初始化向导第 1 步或设置页「Telegram Bot」改；换 token 后界面提示重启服务（在跑的 Bot 仍用旧 token）。

### 5.2 音乐源（频道）管理

**FR-SRC-01（P0）添加源**

输入任一种：

- `@username`
- `https://t.me/username` / `https://t.me/+invite`
- 数字 `chat_id`（含 `-100` 前缀）

系统解析并保存：id、标题、用户名、类型（channel/group/user）、能否访问历史、头像 URL（可选缓存）。

无法访问时给出明确原因：未加入、账号被封禁、链接失效、不是对话。

添加成功后**只加源，不做任何拉取**（v0.10 取消同步子系统）：不建任务、不下载、不扫历史。频道里的歌靠实时搜索（FR-SEARCH-01）找到后按需下载——「加了源但什么都没发生」是**预期行为**，因为搜索是实时的。**频道源**只参与**逐源模式**（`search_mode=sources`）的搜索；切到全账号模式后搜索不再经过频道源列表（源配置保留，切回来即恢复）——**在线源（ChKSz）不在此列**：它在两种模式下都参与，见 FR-SRC-06（v0.16）。

**FR-SRC-02（P0）源属性**

源上只有**身份**与**启用开关**——一个源就是「一个对话 + 要不要参与搜索」：

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| 启用 | 是否参与搜索（`search_mode=sources` 时） | 开 |

身份字段（`id` / `telegram_chat_id` / `username` / `title` / `type`）由添加源时 `get_chat` 解析写入，不在界面上编辑。

> **v0.15 决策（删除死配置）**：原「媒体范围」「源级过滤」「源级保存根目录」「源级模板覆盖」「备注」五项**连同 `sources` 表的对应列一起删除**。判据是「没有任何执行者」——`scope_allows` / `SourceFilters` 只有单测在调（生产代码零调用），三项 override 从未进过 `render_path`（它只吃全局 `TemplateConfig`），`note` 没有任何界面或链路读取；而 `PUT /api/sources/{id}` 每次还把三项 override 与 note 无条件写成 `NULL`。留着等于让 `sources` 表「看起来有按源过滤与按源命名覆盖这两个能力」（同 v0.10 删「自动同步」开关的理由）。将来若真要在下载路径上做源级过滤/覆盖，按 FR 重新立项再加回，不做「先存着」。

**FR-SRC-03（P0）编辑 / 停用 / 删除**

- 停用不删历史。
- 删除源：可选「仅移除源」或「同时删除该源下载记录（不删磁盘文件）」。
- 不提供「一键删磁盘文件」为默认操作，避免误删曲库。
- **音乐源页上还有一组「不是源」的条目**：在线音乐源（网易云 / QQ 音乐 / 酷狗，FR-SRC-06）在「TG 音乐源」段之外单独成一张卡，**没有添加与移除，只有启用开关**——它们不是 `sources` 表的行（那张表是 Telegram 对话的 CRUD），本节的三条动作对它们一概不适用（v0.16）。

**FR-SRC-04（P1）历史回溯 —— 已取消（v0.10）**

- 不提供「从最新往回扫 N 条 / 扫到某日期」这类批量拉历史：那是把频道历史搬进本地库的同步操作，与 v0.10「不做任何同步」的决策冲突。
- 需要老歌时用实时搜索（FR-SEARCH-01）逐首/批量下载；实现侧的 `iter_messages`、`POST /api/sources/{id}/backfill`、游标字段与回溯对话框一并删除。

**FR-SRC-05（P1）源探测**

- 列出当前账号对话中「标题/用户名含 music、flac、mp3、无损、歌单 等关键词」的候选（关键词按词边界匹配，避免 `ost` 命中 `host` 这类误报），供一键添加；命中关键词作为该候选的标签，用于筛选。
- 每条候选展示频道名 + 句柄（或类型）+ 成员数（Telegram 未提供时留空，不猜）。
- 已添加为源的对话不再出现在候选里；非自动全量加入。
- 未登录时不返回空列表假装「没有候选」，而是明确报未登录（登录后才可能读到对话列表）。

**FR-SRC-06（P1）在线音乐源（ChKSz，v0.16）**

- 除 Telegram 音乐源频道外，可接入 **ChKSz**（`https://api.chksz.com`，可自建）作为**在线源**：搜索覆盖**网易云 / QQ 音乐 / 酷狗**三个平台，下载与试听可指定音质档位（档位是语义档位，由 `GET /api/settings/qualities` 下发）。设置页写入 API Key，Key 只存 `config.yaml`（NFR-02），不入库、不回显。
- **逐平台启停**：settings 表里的 `chksz_providers`（CSV，平台键 `163` / `qq` / `kugo` 的任意子集，**空串 = 三个全关**）是「哪些在线平台在跑」的**唯一事实源**；旧键 `chksz_enabled`（单个总开关）由 migration 007 迁移后删除，`GET /api/setup/status.chksz_enabled` 保留但降为**派生布尔**（至少一个平台在跑且有 Key）。**判据**：逐平台开关必须有自己的执行者——「总开关 + 逐平台开关」两层门里，外层那道门在别的页面上，用户在音乐源页点开关会「点了没反应」，而那是他唯一能看到的开关。（放弃的方案：保留总开关、在它关闭时把逐平台开关置灰——那只是把「点了没反应」换成「点不动」，用户仍然不知道为什么。）
- **不占 `sources` 表**：那张表是 Telegram 对话的 CRUD（`telegram_chat_id` 唯一、`type` 为 channel/group/user），把三个平台写成不可增删的假行会让音乐源页出现删不掉的条目。故它们**只被列在音乐源页的「在线音乐源」段**（恒定三行 = 平台名 + 下面标 `ChKSz` + 开关，`GET /api/sources/online`；开关走 `PUT /api/sources/online/{provider}`），**没有添加与移除，只有启用开关**；没配 Key 时三行照旧返回（`enabled` 全为 false）并在段内给去设置页填 Key 的提示——列出来是为了让人知道「这个能力在、缺的是 Key」，藏起来只会得到「文档说有、界面找不到」。
- **设置页那个开关是批量开关**：开 = 三个平台全写进 `chksz_providers`，关 = 清成空串（全部停用）；逐平台开关只在音乐源页。两个入口写的是同一个键，没有「谁先谁后」。
- **两种搜索模式都参与**：搜索页「搜索范围」一行两种模式都渲染，逐源模式列频道 + 在线源，全账号模式**只列在线源**（频道源在该模式下不参与）；在线源药丸两行 = 平台名 + 下面标 `ChKSz`。因此导航里的「音乐源」**两种模式都保留**（v0.16 推翻 v0.14 的按模式收起——那一页是在线源的唯一启停入口，不再是用不上的页面）。搜索侧的扇出、缓存与 `meta` 语义见 FR-SEARCH-01。

### 5.3 搜索

**FR-SEARCH-01（P0）关键词搜索**

- **两种模式**（`search_mode`，v0.14；设置页与向导第 3 步可切，保存即生效）：
  - `sources`（默认）**逐源搜索**：范围 = 已添加且启用的音乐源，可多选；逐个频道各查一次，结果按来源频道分门别类，单源失败只影响该源。
  - `global` **全账号搜索**：范围 = 账号加入的全部对话（含未添加为源的频道），**不需要频道源**；一次服务端 `messages.searchGlobal` 请求取回（频道再多也只是一次调用），结果按全局时间序混排、无法限定源集合（传了 `source_ids` 时按 `chat_id` 在本地过滤），且**单次失败即整次失败**——限流以错误透出，没有「逐源不可达」这一档。**v0.16**：这条链路上**已启用的在线平台照常参与**（FR-SRC-06）——在 `searchGlobal` 之外各起一路取数，与逐源模式共用同步窗口、二级缓存、合并、去重、排序与切页，结果合进**同一页**；故 `partial` / `pending_sources` / `unreachable` 在 `global` 下也可能非空（在线源那一档的失败只让它自己缺席，不废掉整次搜索）。`source_ids` 里的负号 scope 按平台过滤，**只给负号时频道结果被过滤掉**。
- 匹配字段（可勾选）：音频标题、表演者、文件名、消息 caption、专辑（若 Telegram 音频对象有）。勾选后按所选字段在本地过滤；认不出的字段名忽略（不因为字段名对不上就把结果筛空）。
- 使用 User Client 搜索（优先服务端 `messages.search` / `messages.searchGlobal` + `filter=Audio`），结果分页。
- **逐源并发**取数（并发上限 `search_fanout`，默认 4——交互式搜索要的是别把账号打进 FloodWait，不是吞吐），单源失败只影响该源。
- **二级缓存**（v0.11）：L1 进程内 LRU + L2 SQLite；逐源模式粒度 = 关键词 × 源（同一关键词下各源各自命中），全账号模式粒度 = 关键词 × 全局窗口（保留 scope `0`，不依赖任何源行），**v0.16** 起该模式下追加扇出的在线平台各按自己的负号 scope 记账（粒度仍是「关键词 × 源」）；TTL 默认 15 分钟；`refresh` 可强制绕缓存重取。同一关键词的并发请求合并成一次上游调用。
- **同步窗口**（v0.11）：`search_sync_window_ms`（默认 4000）内回来的源进本次响应，超窗的源**不取消、不等待**，转后台补齐并写缓存；本次响应带 `partial` 与 `pending_sources`，界面点名提示——**限流要可见，少给结果也要可见**，绝不静默截断。（`global` 里 Telegram 那一半只有一次上游调用，不存在窗口与补齐；**v0.16** 起这条链路上追加扇出的在线平台照常有窗口与后台补齐；**v0.17** 起这条链路的等待窗口独立成 `global_sync_window_sec`（默认 8000，常量、界面无旋钮）——平台是追加扇出，池子齐了再排才有意义。）
- 无结果、源不可达、FloodWait 要可见。
- 分页语义（v0.11）：在**合并后的结果集**上切页（不是按各源上游 offset 切），故翻页不重不漏；`page_size` 默认 20、上限 100。同一轮翻页共用一个「定序前缀」——窗口加深会让整体次序变动，若每页都按当前窗口直接切，就会出现重复行与丢行（实测过）；新发现的条目追加在已发出前缀之后。全账号模式共用同一套前缀与切页（上游没有 offset 参数，深翻页靠把窗口要得更深）；**v0.16**：全账号模式的翻页前缀还要带上**本次在跑的在线 scope 集合**——多开一个平台，卡片集合就变了，前缀沿用旧值会把新平台的卡片当成「已收录」而丢行。**v0.17**：全账号模式的取数窗口按 `GLOBAL_FETCH_STEP=100` 向上取整（`ceil((page+1)*page_size/100)*100`）——因为这条链路只有一次上游调用、没有「每源 need 条」，窗口就等于一页时首页池子只有 20 条，排序/去重/筛选都在 20 条上做，同源转发被去重后甚至填不满一页；取整后页 0–4 只打一次上游，页 5 抬到 200，取不满窗口即到底。
- 响应 `meta.mode` 回报本次实际走的链路（`sources` / `global`）。

**FR-SEARCH-02（P0）结果卡片**

每条至少展示：

- 封面（有则显示，无则占位）
- 标题、艺术家、时长、文件大小、扩展名/MIME
- 来源频道、消息日期、message_id
- caption 摘要
- 「试听」「下载」「复制链接」「打开 Telegram」；已下载项试听走本地文件。

**FR-SEARCH-03（P0）二次筛选**

- 时长区间、大小区间、日期区间、扩展名（mp3/flac/m4a/ogg/wav 等）。
- 排序：相关度（默认）、日期、时长、大小。
- **v0.11**：上述筛选与排序由服务端执行（入参 `filters` / `sort`，见 SDD §2.6），不再是「收了参数不消费」。筛选区间里**取不到值的卡片一律不通过**（筛「时长 ≥ 3 分钟」时，时长未知的卡片无法证明它满足，放进来就是编造）；非法值（负数、未补零的日期）忽略而不报错。相关度用「命中词数 + 命中质量（整字段 > 前缀 > 子串；标题 > 表演者 > 说明）」排序；**v0.13**：名字分不出时大文件在前（大小未知垫底），日期只在大小也相同的时候比（新→旧）。
- 筛选与排序的作用范围是**本次已取回的窗口**（窗口深度由页码与每页条数决定），不是全库。
- 界面控件：**排序有控件**（搜索页「搜索条件」里的四选一药丸，改动即按新次序从第 0 页重取）；**时长区间、大小区间、日期区间、扩展名不做界面控件**（2026-09-26 裁定）——`filters` 入参保留、服务端照旧执行，只服务 API 调用方。

**FR-SEARCH-04（P1）批量选择**

- 当前页全选、跨页勾选框、一键「下载所选」。
- 已在历史中存在的条目标记「已下载」，默认不重复入队（可强制）。
- **v0.11**：结果列表逐页追加（服务端在完整结果集上切片，追加时按「频道 + 消息 id」去重）；跨页勾选在已载入的行上累计。**v0.17**：追加方式由「加载更多」按钮改为**触底懒加载**——列表底部哨兵进入视口（提前 300px）即自动续页，页脚只留「已载入 n 首 / 加载中 / 已加载全部」状态；连续三页一行业没多即停（服务端 `has_more` 只是「上游可能还有」的上界）。搜索进行中给**进行中动画**（线型进度条不确定态 + 模式相关说明 + 结果区骨架行），因为全账号搜索现在要取更深的窗口、等更久。

**FR-SEARCH-05（P2）保存搜索器**

- 命名一组关键词 + 源 + 过滤，定时执行（订阅式）。

### 5.5 下载引擎

**FR-DL-01（P0）队列**

- 全局队列，状态：`queued` / `downloading` / `paused` / `success` / `failed` / `skipped` / `cancelled`。台账里只有下载任务一种类型（`type='link'`，来源可以是搜索/链接/Bot）；同步任务随 v0.10 取消。
- 终态（失败/跳过/取消）任务行在仪表盘上除「重试」外可「清除」（`DELETE /api/downloads/{id}`）：只删台账行，历史行与已落盘文件保留。
- 并发数可配，默认 3，上限建议 8（可在高级设置放开，但 UI 警告 FloodWait）。
- 全局暂停/恢复（参考 Web 的 Downloading/Stop）。

**FR-DL-02（P0）进度**

- 单任务：已传字节、总字节、速度、ETA。
- 全局速度。
- Web 至少 1s 刷新；优先 SSE/WebSocket，可降级轮询。

**FR-DL-03（P0）完整性**

- 下载到临时目录，校验大小（有 `file_size` 时必须一致），通过后再移动到目标路径（参考项目 `_check_download_finish` + temp→save）。
- 文件名非法字符清洗、Windows 保留名、路径长度截断（参考 `validate_title` / `truncate_filename`，上限约 230 字节）。

**FR-DL-04（P0）失败与重试**

- 记录错误码/文本（含 FloodWait 秒数）。
- 自动重试：默认 3 次，指数退避；FloodWait 等到期再试。
- 手动「重试失败项」：以**失败的历史记录**为准逐条重排——该行当前挂着的任务还在任务台账里就复位它（`POST /api/downloads/{id}/retry`），台账里已无对应任务（例如台账行被删过）则按 `chat_id`/`message_id` 重新入队（`POST /api/downloads`）。

**FR-DL-05（P0）去重**

默认跳过，若命中任一：

1. 同一 `(chat_id, message_id)` 已成功。
2. 同一 Telegram `file_unique_id` 已成功。
3. 目标路径已存在且大小一致。

Web 可开「强制重新下载」。P1 可增加音频指纹（chromaprint）可选去重，默认关。

**FR-DL-06（P1）断点续传**

- 若底层客户端支持 offset 续传则启用；否则至少保留临时文件，失败不污染目标目录。

**FR-DL-07（P1）封面**

- 下载 Telegram 音频缩略图，供 Web 展示；可选嵌入到音频文件（见 FR-META）。

**FR-DL-08（P1）浏览器下载（不入队）**

- 搜索结果的第二个下载动作：把这首取回服务端临时区，交给浏览器存到**本机浏览器的下载目录**。它**不写 `save_path`、不写 `history`、不参与 FR-DL-05 去重、不占试听缓存预算**（同一首可以反复存）；与「下载」键的差别就是**落点**，不是取数链路——来源索引与音质档位与正式下载同源。
- **同一首歌在 TTL 内重复点直接复用**：判据是 `provider + chat_id/message_id + ref + 档位`（档位也算：320k 与母带是两份不同的文件），命中即返回**同一个 token 与地址**、不重打上游、不重写磁盘，并把这份的 TTL 续期（用户正在用它）。连点两次时，后到的请求在取数槽内二次查找，命中先到的那份而不必排队等它下完再下一次。文件不在或被清掉则老老实实重取——复用只省重复的活，不改「取不到就报错」的语义。
- 准备（`POST /api/search/browser-download`，`{message_refs:[…]}`，`quality` 可选）在服务端完成取数：文件名走**当前文件名模板** + 扩展名，三档来源按可信度排：**上游实测**（在线源会静默升降档，不按请求的档位命名）→ 卡片 `ext`（小写去点 + 按 `AUDIO_EXTS` 白名单收口：`FLAC` 归一成 `flac`，`.`/认不出的值丢掉）→ 卡片 `mime` 推定；都没有就不带扩展名，不编一个错的容器名。**这一档必须有**（v0.18 实现回写）：Telegram 源取数不回报 `ext`，搜索卡片的 `file_name` 也可能没有点（document 音频常见），而请求体只带 `title`/`artist` 时服务端也走不到正式下载那条「取消息补全 meta」的路——漏掉它，用户拿到的是双击打不开的无扩展名文件。卡片声明了字节数时按它校验（FR-DL-03），不符就不交出去；若此刻用户在设置页点了「清理缓存」把这份临时文件删了，按业务错误处理（不是裸 500），重新点按钮即可。**响应是 SSE 进度流**（`text/event-stream`）：取数途中按拍推 `{"state":"preparing","loaded","total"}` 字节进度，结束推一条 `ready`（`{token,file_name,size,url}`）或 `failed`（v3.28）。**失败落在流内终态**而不是 HTTP 400——响应头在取数开始时就发出去了，失败要到途中才知道；`failed` 的形状仍是标准错误包络 `{"error":{"code","message"}}`，界面**行内**展示。取数不放 GET 的理由不变：浏览器顶层导航读不到响应体，放 GET 只会把用户带到一个 JSON 错误页。
- 交付（`GET /api/search/browser-download/{token}`）：`Content-Disposition: attachment`（非 ASCII 文件名走 RFC 5987）。token 在 **TTL（默认 2 小时）内可重复取**——`FileResponse` 自带 Range（206），浏览器分段取与下载管理器暂停后的续传都命中同一份文件；「取走即作废 + 立刻删文件」会让这类下载断在半路，故临时文件**不随某一次响应删**，由 TTL 与并存上限（`MAX_PREPARED = 8` 份，超出删最旧）回收。文件在 `data/temp/browser/`（与下载分片同区不同前缀，清扫只扫这个子目录）；过期或被挤掉后同一地址是 404，用户重新点按钮即可。
- **进度与取消（v3.28）**：`prepare()` 把取数层的字节回调透传给 `MusicSourceProto.fetch`，路由层按 0.4s 一拍推给前端；`total` 报不出来时（部分在线源没有 `Content-Length`）界面退**不确定态**，不编造百分比。**客户端断开即取消**：流一断，服务端 `task.cancel()` 停掉取数，半截分片由 `prepare()` 的取消分支清掉——用户改主意时不该让上游继续把这首歌拉完。前端另有一次**导航前探测**：`HEAD /api/search/browser-download/{token}`（204 / 404，不读正文）——token 过期时 GET 回 404，直接顶层导航会把**整页**带走、只剩一个错误页。
- 取数并发与试听槽同口径但各用各的（并发 1）：连点会打满上游吃 FloodWait，但它不该把试听槽占死，反之亦然。
- **回收复用已有的入口与时机，不另起一套 UI**（v0.18）：临时区的字节与份数并进设置页「下载与试听」卡的**缓存占用**（`GET /api/settings/cache` 新增 `browser_bytes`/`browser_count`；**不并进 `total_bytes`**——那个数对着试听/封面那份字节预算看，混进来会变成「超上限却没有东西被淘汰」的假象），**清理缓存**按钮一并清（`POST /api/settings/cache/clear`），启动装配后随试听缓存的修剪一起扫一次（TTL 与并存上限不只在下次点击时生效）。**不把临时文件塞进试听缓存本体**：那张表的主键 `(chat_id, message_id)` 不含音质，同一首歌「试听 320k → 浏览器下载母带」会互相命中错的那份；且它是可随时淘汰的 LRU（一首无损就能挤掉几十首试听），淘汰时会删掉浏览器正在分段取的文件。

### 5.6 命名与保存路径

这是相对参考项目的核心升级：由「前缀列表」改为「模板」。

**FR-NAME-01（P0）全局模板**

两项独立配置：

- **目录模板**（相对 `save_path`）
- **文件名模板**（不含扩展名，扩展名由真实文件决定）

示例默认：

```
save_path: D:\Music\Telegram
dir_template: {artist}/{album}
file_template: {track:02d} {title}
```

结果：`D:\Music\Telegram\周杰伦\范特西\03 晴天.flac`

**FR-NAME-02（P0）占位符**

| 占位符 | 来源 | 缺省回退 |
| --- | --- | --- |
| `{title}` | `audio.title` → 去扩展名的 `file_name` → caption 首行 → `message_{id}` | 必有 |
| `{artist}` | `audio.performer` → caption 解析 → `Unknown Artist` | |
| `{album}` | 若有（部分客户端会带）；缺省省略该目录段，不强制 `Unknown Album`（见 FR-NAME-07） | |
| `{track}` | 若有 | 空则省略 |
| `{duration}` | 秒，可 `{duration:%M:%S}` | |
| `{year}` `{date}` `{date:%Y-%m}` | 消息日期 | |
| `{channel}` `{channel_id}` | 源标题 / id | |
| `{message_id}` | 消息 id | |
| `{file_name}` | 原始文件名（去路径） | |
| `{caption}` | 消息说明，截断可配 | |
| `{ext}` | 仅文件名模板可用，一般不手写 | |
| `{bitrate}` `{size}` | 能取到才填 | 空 |
| `{unique_id}` | `file_unique_id` 短前缀，防撞名 | |

支持简单过滤器：`{caption:truncate:80}`、`{track:02d}`。非法路径字符一律替换为 `_`。

**FR-NAME-03（P0）空字段规则**

- 目录段若整段为空则省略（`{album}` 无值时不建 `Unknown Album` 文件夹）。`{artist}` 仍回退为 `Unknown Artist`。不生成多余分隔符。
- 文件名若最终为空，回退 `{message_id}`。
- 同名冲突：`title.flac`、`title (1).flac`，或附加 `{message_id}`（策略可配，默认加序号）。

**FR-NAME-04（P0）源级覆盖**

- 每个源可覆盖 `dir_template` / `file_template` / `save_path`。
- Web 提供实时预览：用一条样例元数据渲染路径。

**FR-NAME-05（P1）caption 解析规则（可选）**

**FR-NAME-07（P1）Navidrome / Jellyfin 友好默认目录（原 S-03）**

- 出厂默认模板为 `{artist}/{album}` + `{track:02d} {title}`，媒体服务器可直接扫描 `save_path`。

**FR-WEB-02（P0）认证**

- `web_login_secret` 为空且仅监听 127.0.0.1：可不登录。
- 监听 0.0.0.0 时强制要求密码；被拒时日志（stderr 与 `data/logs/app.log` 都有）除拒绝原因外必须给出**可执行的修复路径**：配置文件的绝对路径（`<TGM_BASE_DIR>/data/config.yaml`，并点出 compose 部署下的宿主机位置）、等价的环境变量 `TGM_WEB_LOGIN_SECRET`、以及显式放行的 `TGM_WEB_LOGIN_ENABLED=false`——只报「拒绝」不给出路的日志等于让人去翻源码。

### 5.8.2 试听

**FR-PLAY-01（P1）已下载播放**

- 下载页的历史记录行提供播放（文件仍在磁盘上时）。音频从本机 `save_path` 经认证 HTTP 流出（`Range`），不把目录裸暴露。
- 底栏播放器：播放/暂停、拖动进度、音量、上一首/下一首（当前列表上下文：下载页的筛选结果或搜索已下载项）。
- 同一时刻一首；切歌停上一首。
- 浏览器不支持的编码（少见 codec）：提示「无法在浏览器播放，可打开本地文件」，不崩溃。目标格式：mp3、m4a/aac、ogg/opus、wav；flac 在 Chromium 可用则播，否则同样提示。

**FR-PLAY-02（P1）搜索结果试听（未下载）**

- 搜索卡片「试听」：用 User Client 拉取该消息音频，写入 `temp/preview/`，再按 FR-PLAY-01 同样方式流出。
- 试听不是下载入队，不写 `save_path`、不写成功历史（可写 preview 缓存记录）。
- 缓存上限可配，默认 512MB 或 50 个文件，LRU 淘汰。试听与封面**共用一个字节上限**：试听按最近访问时间淘汰，封面（同目录、不进 `preview_cache` 表）按文件 mtime 淘汰；设置页显示缓存占用并可一键清理（清理只删缓存，不动曲库与历史）。设置页那行占用另单列**浏览器下载待取走的临时文件**（FR-DL-08）：它不进这份字节预算，清理缓存会一并清掉。
- 用户点「下载」仍走正式队列；若预览文件已完整且校验通过，允许直接搬到目标路径以避免二传（可选优化，失败则正常下载）。
- FloodWait / 无权限：试听按钮显示错误，不影响其它卡片。
- 不实现 Telegram 流式边下边播为 P1 必达；允许「先缓冲到可播再开始」（目标：普通 5–10MB 曲 < 15s 出声，受网速限制须显示缓冲状态）。

**FR-PLAY-03（P1）播放与下载互不阻塞**

- 试听占用独立于 `max_download_task` 的 1 个预览槽，默认并发预览 1，避免搜列表连点打满 FloodWait。
- 下载队列不因播放暂停。

### 5.9 配置与数据持久化

**FR-CFG-01（P0）**

- 密钥：`config.yaml` 或 `.env`（`api_id`、`api_hash`、`bot_token`、`web_login_secret`、`web_login_enabled`、代理）；Docker 下支持 `TGM_*` 环境变量与 `TGM_BASE_DIR` 路径布局覆盖。
- 密钥文件位置 = `<TGM_BASE_DIR>/data/config.yaml`，与 SQLite、会话同处数据目录：**随数据卷一起持久化**，不要求用户为它单独挂 bind mount；向导首次保存时自动创建；旧位置的 `config.yaml` 启动时自动迁移。env 同名键优先，给全了就无需该文件。
- 部署路径（FR-CFG-02）同源：`config.yaml` 的 `save_directory`/`session_directory`/`temp_directory`，或同名 `TGM_*` 环境变量（env 优先）。
- 业务数据：SQLite（源、任务、历史、游标、设置中的模板）。
- 不把下载历史只写 YAML。

**FR-CFG-02（P0）路径**

```
save_path/          # 用户曲库
temp/               # 下载中
temp/preview/       # 搜索试听缓存（LRU）
sessions/           # telegram session
data/app.db         # sqlite
logs/               # 运行日志（app.log 只保留最近 500 行）
```

- 默认相对 `TGM_BASE_DIR`（源码根；Docker 为 `/data`）展开，默认目录名 `downloads`（曲库）、`sessions`、`temp`；`data/`、`logs/` 固定相对基准目录，不单独配置。
- 三项可覆盖为绝对路径：`save_directory`（曲库）、`session_directory`（会话）、`temp_directory`（临时与试听缓存，`temp/preview` 为其子目录）。
- Docker 示例：`/data/downloads`、`/data/sessions`、`/data/temp`（`docker-compose.yml` 以 `TGM_SAVE_DIRECTORY` 等指定并挂载同名卷）。
- Windows 上 `/data/...` 这类无盘符写法锚定到基准目录所在盘（如 `C:\data\downloads`），不随进程当前盘漂移。

**FR-CFG-03（P1）导出/导入源列表**

- JSON/CSV：username、标题、启用状态。不含 session。

### 5.10 运维与安装

**FR-OPS-01（P0）**

- `README`：申请 API、登录、添加频道、模板说明、代理。
- 一种启动方式：`python -m app` 或等效脚本。

**FR-OPS-02（P1）Docker Compose + Web 初始化**

- Linux 为主运行环境，Docker 部署：卷挂载 `save_path`（`/data/downloads`）与数据目录 `data/`（→ 容器 `/data/data`，`TGM_BASE_DIR=/data`）：密钥 `config.yaml`、SQLite、会话、中转与日志都在里面，只此两处。
- 首次部署 `docker compose up -d` 后，浏览器打开 Web **在界面内完成全部初始化**，向导固定三步，不做「先 compose run 再 up -d」的前台交互：
  1. **密钥与代理**：`api_id` / `api_hash` / `bot_token`（可选）/ 代理（可选，可关闭）。保存前逐项校验（数字位数、十六进制长度、`bot_token` 形状、端口范围），**校验不通过就不写 `config.yaml`** 并把待修项一次列全；写入后清空「走代理」表示直连（清除代理段）。
  2. **登录账号**：手机号 + 验证码（2FA 按需输入云密码），会话文件生成在数据目录的 `data/sessions/`。密钥未齐备时不允许进入本步。
  3. **搜索模式**（v0.14）：在「逐源搜索」与「全账号搜索」之间选一个（两种随时可在设置页改）。选「逐源搜索」时本步继续给出音乐源配置（可跳过）：从账号对话推荐候选，或粘链接/`@用户名` 手动添加，邀请链接（`t.me/+…`）明确拒绝并说明「先用账号加入再粘用户名」；选「全账号搜索」时**不再需要音乐源**，本步直接说明可进控制台。
- **放行判据 = 密钥齐备 + 已登录**：未满足时 Web 强制停留在向导，其余页面不可达；音乐源可跳过（全账号模式下第 3 步根本没有音乐源配置），进控制台后在「音乐源」页补。前端闸门在**渲染期**判定——只有确认 `complete=true` 才渲染控制台，否则整页就是向导（不先闪一下控制台再跳走）；状态接口没取到（后端没起、401）也按未初始化处理，停在向导并在页头写明原因（首次部署只有这一个入口），不出现永久加载态。
- **前端产物**（`web/dist`）跟随**代码**位置（源码根；Docker 镜像内为 `/opt/app/web/dist`），不跟随 `TGM_BASE_DIR`——Docker 里数据在 `/data`、代码在 `/opt/app`，用数据目录拼路径会让首屏 404，向导不可达。产物在别处时用 `TGM_STATIC_DIR` 覆盖。产物缺失时非 `/api` 请求返回一段构建说明（`cd web && npm install && npm run build`，或 `./run.sh`；Docker 需在构建镜像前先构建），而不是一行 404 JSON。
- 向导内保存的密钥对**尚未连接**的客户端立即生效（保存后可直接登录），不需要为了登录先重启；已连接客户端在界面提示重启后生效。
- 配置修不好（例如代理不可达）时**服务仍要起得来**：启动期连不上 Telegram 只记警告，Web 与向导照常可用，否则用户没有入口去改配置。
- 手机号与验证码只走本机、不进日志（FR-OPS-03）。
- 初始化密钥由 `POST /api/setup/secrets` 写入 `config.yaml`（不入库）。文件位置 = `<TGM_BASE_DIR>/data/config.yaml`（Docker 为 `/data/data/config.yaml` = 宿主机 `./data/config.yaml`）：它跟 SQLite、会话在同一个数据卷里，**容器重建（`docker compose up -d`）后密钥仍在，不需要重走初始化**；文件由向导首次保存自动创建，旧位置 `<TGM_BASE_DIR>/config.yaml` 启动时自动迁移。纯 env 部署（`TGM_*` 给全）可以不落文件。向导内保存对尚未连接的客户端立即生效，已连接客户端按上面的重启提示处理。
- **重新执行初始化**（设置页入口，`POST /api/setup/reset`）：删除 `config.yaml` 的 `api_id`/`api_hash`/`bot_token`/`proxy`，退出登录并删除 User 与 Bot 会话文件（换 token 后旧 Bot 会话会复用旧身份），随后回到向导第 1 步。**保留**：`web_login_secret`/`web_host`/`web_port`、部署路径、下载文件、下载历史、音乐源。前端随后按放行判据被闸门送回 `/setup`。

**FR-OPS-03（P1）日志**

- 级别可配；默认不把手机号、验证码写入日志。

## 8. 数据模型（逻辑）

### 8.1 Source

`id, telegram_chat_id, username, title, type, enabled, created_at, updated_at`

（`auto_sync` / `sync_interval_sec` / `last_message_id` 随 v0.10 取消同步删除；`media_scope` / `filters_json` / `save_path_override` / `dir_template_override` / `file_template_override` / `note` 随 v0.15 删死配置删除。）

### 8.2 Track / History

`id, source_id, chat_id, message_id, file_unique_id, file_id, title, artist, album, duration_sec, file_size, mime, ext, caption, message_date, save_path, status, error, created_at, finished_at`

唯一约束建议：`(chat_id, message_id)`；另建 `file_unique_id` 索引。展示用 title/artist/album 在 FR-TAG-02 保存后与文件内标签对齐。

### 8.3 Task

`id, type (search|link|bot|sync|preview), payload_json, status, progress_bytes, total_bytes, speed, history_id, created_at`

`history_id` 指回这一行下载对应的历史行（§8.2，可能为 `null`）；一行下载记录可以挂多条任务（每次重试多一条），列表与状态筛选以历史行的 `status` 为准（FR-WEB-03），`GET /api/history` 每行的 `task_id` 取该行最新的一条任务。

### 8.4 Settings

键值表：`save_path, dir_template, file_template, date_format, max_download_task, web_host, web_port, preview_cache_max_bytes, notify_web, ...`

## 9. 界面信息架构（示意）

```text
侧栏 260px（≥1024px 展开，侧栏:主栏 ≈ 1:4~1:5；<1024px 收为顶栏汉堡抽屉）
  音乐库（图标 + 系统名 + 识别码）
  仪表盘 / 搜索 / 下载（进行中计数）/ 音乐源 / 设置 / 日志（错误计数）

顶栏 64px（全站常驻，不随路由变化）
  页面标题 | 全局搜索（Ctrl K → /search?q=，源选择留在搜索页）
  在传任务数 | 总速率（没有在传时不占位）
  外观（顶栏单键在浅/深间翻面，图标随之换；三档「跟随系统 / 浅色 / 深色」在设置页选）| 通知 | 连接状态 + 账号头像

内容区（左对齐，max-width 1100px，内边距 24px）
  页头：标题 + 一行上下文 + 右侧计数或动作
  主体：卡片内的数据表/列表行；数值列等宽右对齐

播放条 76px（全站常驻）
  封面 / 标题 / 艺人 → 随机 · 上一首 · 播停 · 下一首 · 循环 → 时间码 + 进度（线型或波形，可拖动）→ 音量、队列
```

- 仪表盘首屏：淡绿状态卡承载正在写入的传输（真实字节/速率/剩余）+ 最近落盘路径；下方为队列事实与最近入库。
- 音乐源「添加」：链接输入 → 服务端校验 → 列表追加；失败即为行内错误（原因 + 修复）。
- 音乐源「移除」：确认对话框，可选「同时删除该源的历史记录」。
- 音乐源「TG 音乐源」段（v0.16）：页头（标题 + lede + 计数）之下的第一张卡 = 统计卡（总数 / 已启用）+ 添加表单 + 频道列表；**全账号搜索模式下整段收起**（含统计卡与表单，配置保留、切回逐源即回来），lede 换成「页面只剩在线音乐源」、计数消失、页首提示写明「已在这一页收起」并给回逐源的按钮。
- 音乐源「在线音乐源」（v0.16）：上述段之外恒定三行 = 平台名（下面标 `ChKSz`）+ 逐平台开关；**不是 `sources` 表的行**，没有添加与移除，没配 Key 时给去设置页的提示；**两种搜索模式都参与**（全账号模式下页面只剩这一段），导航里的「音乐源」两模式都在。
- 设置「搜索模式」：两张可选卡（逐源搜索 / 全账号搜索）+ 各自的差别说明 + 一行「当前模式的差别」提示（全账号下频道源不参与、在线源照常参与；音乐源页两种模式都在导航里）；点选即保存生效，不走「保存更改」按钮。
- 设置「在线音乐源」（v0.16）：API Key + 「启用在线源」**批量**开关（开 = 三个平台全开，关 = 全部停用）+ 两个音质档位；逐平台开关在音乐源页。
- 设置「模板」：左右分栏，左编辑，右实时预览落盘路径；并发与试听缓存上限标注「下次启动生效」。
- 设置「账号与连接」：账号行（灯 + 显示名/用户名/Premium）+ 退出登录（确认对话框）；Bot token 与代理各自一张卡，保存后按 `restart_required` 说明「立即生效」还是「重启服务」；末尾「重新执行初始化」卡（确认对话框里写清会清掉什么、保留什么）。
- 下载行：状态 / 标题 / 进度 / 时长 / 大小 / 入库时间 / 操作；播放 / 复制路径 / 重新下载，进行中行给暂停 / 继续 / 取消，失败等终态行给重试；落盘路径为行的第二行一级文本（等宽，文件名不省略）。
- 标签编辑抽屉：见 SDD §5.2，后端 `/api/history/{id}/tags` 路由未实现前不提供。

## 10. 接口轮廓（实现用，非对外公开 API）

REST 建议（均需 Web 会话）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/telegram/send-code`、`/api/auth/telegram/sign-in` | 登录步骤（发码/提交码/2FA）；错误码区分 `secrets_missing`/`phone_invalid`/`code_invalid`/`code_expired`/`password_required`/`password_invalid`/`connect_failed` |
| POST | `/api/auth/logout` | 退出 Telegram 账号：断开 User Client 并删除会话文件，保留数据；不动 Web 会话 cookie |
| GET | `/api/me` | 当前账号 |
| POST | `/api/setup/secrets`、`GET /api/setup/status` | 首次部署初始化：校验后保存密钥到 config.yaml / 查询初始化与连接状态（`complete` = 密钥 + 已登录，另含 `search_mode` 与 `chksz_enabled`（派生：有在线平台在跑且配了 Key，v0.16）供前端决定入口形态——v0.16 起导航不再随模式收起，收起的只有仪表盘的音乐源入口与统计卡） |
| POST | `/api/setup/reset` | 重新执行初始化：清密钥段 + 退出登录 + 删 User/Bot 会话，回向导第 1 步 |
| CRUD | `/api/sources` | 音乐源（只有身份 + 启用开关）；`GET /api/sources/discover` 候选源；`POST /api/sources` 只加源（v0.10 起不再附带任何导入任务），`PUT /api/sources/{id}` 只改启用状态 |
| GET/PUT | `/api/sources/online` | 在线音乐源：`GET` 回恒定三行 `{has_key, providers:[{id, provider, title, enabled}]}`；`PUT /api/sources/online/{provider}` body `{enabled}` 写 `chksz_providers` 里的该平台（未知 provider → 404）。它们不是 `sources` 表的行，没有增删（FR-SRC-06，v0.16） |
| POST | `/api/search` | `{q, source_ids, filters, sort, page}`；按 `search_mode` 走逐源或全账号链路，响应 `meta.mode` 回报实际链路 |
| POST | `/api/downloads` | `{message_refs[]}` 或 `{urls[]}` |
| GET | `/api/downloads` | 任务**台账**列表（仪表盘「最近下载任务」与顶栏在传读数在用；下载页的列表走 `/api/history`） |
| POST | `/api/downloads/{id}/cancel` | 取消（另有 `/pause`、`/resume`、`/retry`；`/retry` 复位该台账里的任务） |
| DELETE | `/api/downloads/{id}` | 删除任务台账行（端点保留；合并后的下载页界面不再暴露删除动作） |
| POST | `/api/downloads/retry-failed` | 「重试失败项」：按失败的历史行逐条重排（FR-DL-04） |
| GET | `/api/history` | 分页筛选（`status`/`source_id`/`q`/`page`）；每行含 `task_id`（该行当前任务，可能为 `null`） |
| GET | `/api/history/{id}/stream` | 已下载 Range 音频流 |
| GET/PUT | `/api/history/{id}/tags` | 读/写文件标签；PUT 可带封面 |
| POST | `/api/history/{id}/rename` | 按模板重命名（可选） |
| POST | `/api/preview` | `{chat_id, message_id}` 缓存并返回 preview id |
| GET | `/api/preview/{id}/stream` | 试听 Range 流 |
| POST | `/api/search/browser-download` | `{message_refs:[…]}`（与 `/api/downloads` 同形，`quality` 可选）：把这首取回临时区，响应是 **`text/event-stream`**——若干 `{"state":"preparing","loaded","total"}` 进度帧 + 一条 `{"state":"ready","token","file_name","size","url"}` 或 `{"state":"failed","error":{…}}` 终态。失败**不走 HTTP 4xx**（响应头早已发出），形状仍是标准错误包络；客户端断开即停掉取数（FR-DL-08） |
| HEAD | `/api/search/browser-download/{token}` | 可用性探测：204 / 404，不读正文。前端在顶层导航前问一次，避免 token 过期时把整页带到浏览器的错误页（FR-DL-08） |
| GET | `/api/search/browser-download/{token}` | 附件流（`Content-Disposition: attachment`）：浏览器存到本机下载目录；token 在 TTL 内可重复取（Range/续传），临时文件由 TTL 与并存上限回收（FR-DL-08） |
| GET/PUT | `/api/settings` | 业务配置读写（含 `search_mode`；保存即生效）；另含模板预览 `POST /api/settings/preview-path` |
| WS/SSE | `/api/events` | 进度、日志、预览就绪 |

## 11. 验收标准

**P0**

1. 使用真实 Telegram 测试账号登录后，Web 显示账号名。
2. 添加一个含音频的公开频道，搜索已知曲名能出结果，字段含标题或文件名、时长、来源。未添加的对话不出现在搜索范围。
3. 从搜索结果下载一首，磁盘路径符合当前模板；刷新历史可见成功记录。
4. 修改模板后再下一首，新路径生效，旧文件不被改名。
5. 向 Bot 发送该频道一条音频消息链接，下载成功并回复。
6. 向 Bot 转发一首音频，保存成功。
7. 同一条消息再下，默认跳过并标记 skipped。
8. 下载中点击全局暂停，传输停止；恢复后继续或重入队（行为在实现时写进帮助，须一致）。
9. 故意填错误链接，Web 与 Bot 均返回失败原因，不崩溃。
10. 关闭进程再启动，源列表与历史仍在，session 无需重登。
11. voice / 视频消息不会入队；仅 `audio` 与 `audio/*` document。

**P1（随 M4）**

12. 默认模板下载后的相对路径为 `{artist}/{album}/{track:02d} {title}.ext`；无专辑时路径为 `{artist}/{track:02d} {title}.ext`。
13. 设置页切换「按频道归档」预设后，新下载路径变为 `{channel}/{artist}/...`。
14. 浏览器授权通知后，Web 任务完成弹出 Notification；Bot 任务完成仍有 Telegram 回复。
15. 390px 宽下可完成：打开搜索、添加源、查看任务、底栏播放；可切换深色主题。
16. 历史中一首已下载 mp3：点播放后底栏出声，暂停/拖动进度有效；未登录请求 `/stream` 被拒绝。
17. 搜索一条未下载音频：点试听后出现缓冲状态，随后出声；`save_path` 不新增文件；再点下载仍可入队。
18. 打开已下载曲的标签：展示文件内 title/artist；修改 title 保存后，用 mutagen/其它标签工具打开该文件可见新 title，音轨时长不变；历史列表标题同步。
19. 改标签时不勾选重命名：磁盘路径不变。点「按模板重命名」并确认后路径更新，旧路径不留文件。
20. Linux Docker 部署后，Web `/setup` 向导内完成 api_id/api_hash/bot_token/代理保存（写入 config.yaml）与手机号验证码登录，`sessions/` 生成会话文件，重启容器后无需重登。
21. 向导第 1 步填错（`api_id` 位数不对、`api_hash` 非 32 位十六进制、代理端口越界）时**不写 `config.yaml`**，行内一次列出全部待修项；改正后保存成功，且登录立即用新密钥。
22. 密钥已配置但未登录时，除 `/setup` 外访问任何页面都被送回向导；登录完成后放行；第 3 步不加任何音乐源也能进控制台。
23. 代理不可达时点「发送验证码」，界面在可接受时间内给出「连不上 Telegram（当前代理 …）」这类带修复方向的原因，不出现无响应的等待或空泛报错。
24. 向导第 3 步（逐源模式）从账号对话推荐候选（含句柄/成员数/命中标签），一键添加后该候选从推荐列表消失、出现在「已添加」里；添加动作不产生任何任务（v0.10 起不拉取、不导入）。
25. 设置页「Telegram 账号」显示当前账号（灯 + 显示名 / @用户名 / Premium）；点「退出登录」并在确认对话框确认后 `sessions/musicdown.session` 被删除，界面回到向导第 2 步，重新登录仍需输入验证码；下载历史与音乐源不受影响。
26. 设置页改代理或 bot_token 后写入 `config.yaml`：未连接的客户端提示立即生效，已连接客户端提示重启服务；代理的用户名/密码填了才覆盖，留空沿用已存值，且回读不显示。
27. 设置页「重新执行初始化」确认后：`config.yaml` 的 `api_id`/`api_hash`/`bot_token`/代理消失，`web_login_secret` 与 `save_directory` 等部署路径保留；User 与 Bot 会话文件均被删除；界面回到向导第 1 步且各项状态显示为缺失；下载历史与音乐源仍在。
28. 全新部署（无 `config.yaml`、无 `sessions/`、`TGM_BASE_DIR` 指向别处）打开任意 URL（`/`、`/dashboard`、`/setup`）：首屏直接是向导第 1 步，DOM 里没有侧栏/顶栏/播放条，地址栏被 replace 成 `/setup`；把 `TGM_BASE_DIR` 换成任意目录（含 Docker 的 `/data`）都不影响前端产物定位。
29. 前端产物缺失时（本地没构建、`TGM_STATIC_DIR` 指空）：非 `/api` 请求返回构建说明（503 文本），`/api/*` 仍返回 JSON 404，日志记 error；构建后同一进程重启即恢复。
30. 搜索模式可切且两条链路都通（v0.14；**v0.16 改写**）：设置页把模式切成「全账号搜索」后立即生效——仪表盘不再摆音乐源入口与统计卡（**导航里的「音乐源」保留**：在线源在该模式下也参与搜索，那一页是它们的启停入口），搜索页的「搜索范围」一行**仍在**、只是**只列在线源药丸**（频道源在该模式下不参与，故不列）并显示范围说明；此时**一个频道源都没添加也能搜出结果**（范围 = 账号加入的对话，结果行显示各自来源频道）；`POST /api/search` 的 `meta.mode` 为 `global`，且该关键词的 Telegram 侧只打一次上游（同词第二次命中缓存）。**在线源一侧（v0.16）**：音乐源页在全账号模式下只剩「在线音乐源」段——「TG 音乐源」段（两张统计卡 + 添加表单 + 频道列表）整段收起、页头计数消失、页首提示写明「已在这一页收起（配置保留）」，切回逐源后原样恢复；在音乐源页打开网易云 / QQ 音乐 / 酷狗的任意组合后，全账号模式的结果里出现这些平台的卡片（该页两模式都在导航里）；关掉某个平台的开关后它的卡片消失、其余照旧；只配了 Key 而三个平台全关时，`GET /api/sources/online` 三行照常返回且 `enabled` 全为 false，搜索不经过在线源；设置页那个「启用在线源」开关是**批量**开关——打开它后音乐源页三行同时变「开」，关掉则三行同时变「关」（它是唯一能一次改三个平台的入口）。切回「逐源搜索」后入口全部恢复，搜索范围回到已启用（频道 + 在线）源。

31. 搜索结果行点「浏览器下载」：行内出现「准备中」，随后浏览器开始原生下载，文件落在**打开网页这台电脑的下载目录**（文件名为当前文件名模板 + 实测扩展名）；`save_path` 不新增文件，下载页与下载历史不出现新行；同一条地址在有效期内（默认 2 小时）可重复打开（分段取 / 暂停后续传不会断在半路，超过 TTL 的旧地址才是 404）；在线源行先弹音质弹窗，确认文案为「浏览器下载这一档」。上游取数失败（无可用来源 / 限流 / 大小不符）时错误显示在**该行**，页面不跳转。搜索行操作列三颗键不互相挤压（播放 / 入队下载 / 浏览器下载），「大小」列文字不被压住。
32. 容器重建后不重走初始化：向导走完、密钥落在 `<TGM_BASE_DIR>/data/config.yaml`（Docker = 宿主机 `./data/config.yaml`）后，`docker compose up -d`（含改 compose / 拉新镜像 / `down` 后 `up` 触发的重建）与 `docker restart` 都直接进入控制台，`complete=true`；`./data` 里同时看得到 `config.yaml`、`app.db`、`sessions/`。旧位置 `<TGM_BASE_DIR>/config.yaml` 存在时首次启动自动迁移，迁移后旧文件消失、密钥内容不变；纯 `TGM_*` env 部署（无文件）同样放行。

## 12. 风险

| 风险 | 缓解 |
| --- | --- |
| Telegram 限制 User Client 搜索频率 | 缓存、分页、FloodWait 排队 |
| 频道不填 audio 元数据 | caption 正则 + 文件名回退 |
| Windows 路径限制 | 截断、非法字符清洗、提前校验盘符 |
| Session 被踢 | Web 重新登录流程 |
| 用户添加过多源导致同步打满 | 源级开关、全局同步槽位 |
| 版权投诉 | 本地个人工具、不提供分享加速/公开索引 |

## 14. 已锁定决策

| # | 问题 | 决策 |
| --- | --- | --- |
| 1 | 搜索范围 | **由 `search_mode` 决定，默认「仅已添加且启用的音乐源」**（不在账号其余对话中搜 audio）。可选「全账号搜索」= 服务端 `messages.searchGlobal`，范围是账号已加入的全部对话（含未添加为源的频道），此时不需要**频道源**（v0.14）。**v0.16**：「不需要音乐源」只指频道源；**在线音乐源（网易云 / QQ 音乐 / 酷狗）在两种模式下都参与**（逐平台启停见 FR-SRC-06），导航里的「音乐源」页也不再按模式收起。 |
| 2 | Telegram 库 | **Kurigram**（Pyrogram 的活跃分支，导入名仍是 `pyrogram`；User Client + 可选 Bot Client）。 |
| 3 | voice / 视频音轨 | **不含**。仅 `Message.audio` 与 MIME 为 `audio/*` 的 `document`。 |
| 5 | Web 技术 | **后端 FastAPI + 前端 Svelte 5（Vite 构建；样式 TailwindCSS + shadcn-svelte）**。 |
| 6 | 初始化向导 | **三步**（密钥与代理 → 登录账号 → 搜索模式（含逐源模式下的音乐源配置）），**放行判据 = 密钥齐备 + 已登录**；音乐源可跳过（进控制台后在「音乐源」页补），选「全账号搜索」时本步没有音乐源配置。向导排在侧栏导航之外，是未初始化时的全屏闸门。 |

若后续要改上述任一项，先改本文档再动代码。
